## Source-grounded findings

1. **Pressed/selected conflict, priority P1.** `crates/nuraloumi-render-cairo/src/model.rs:287-293` has `selected_id`, `pressed_id`, and scroll offset but no interpolated per-control press phase. `layout.rs:402-432` selects an accent-tinted fill when `pressed_id` equals row ID and independently emits selected outline/rail. Importantly the pressed predicate is **not gated by `enabled`** (`enabled` is computed but not used to gate the pressed fill), so an externally stale/malformed pressed ID may visually press a disabled row. Require `pressed && item.enabled && item.kind.actionable()` for paint; keep selected separate from ephemeral pressed and never synthesize actions in renderer.
2. **Compact controls omit press styling, priority P1.** `layout.rs:937-1147` draws buttons/tabs using `selected(id)` only; `interaction.pressed_id` is ignored. `Button` and `Toolbar` button `enabled` is represented in HitRegion but visual active state is selected, while `Tabs` selected state is persistent. A motion integration seam is the local `button` painter: supply separate ephemeral press progress/tint/inset parameters, leaving hit rect and selected stroke unchanged. Do not animate `Status`/`Breadcrumb`; disabled buttons must remain inert.
3. **Hit-geometry independence feasible.** `model.rs:345-381` has independent `Scene.paint` and `Scene.hits`; `Scene::hit_test` selects only enabled actionable hits. `layout.rs:1016-1026` derives hits from original logical rects rather than inset rounded painted rects; `layout.rs:1125-1135` uses logical slider track. Only modify paint attributes for press motion, never the `HitRegion.rect` or `Scene::hit_test`. Existing `layout.rs:1220+` tests check compact target sizes, disable flags, and 1x/1.5x/2x logical hit equivalence.
4. **48 logical px / 40 px edge gap, priority P1.** `layout.rs:946-958` computes 48px compact rows and wraps toolbars/tabs at floor(width/48), preserving min width, but is not itself the persistent 40px top bar. For panel edge reachability validate `panel.rs` geometry independently with R1-17; do not apply a 48px control height to a 40px layer-shell panel without a deliberate screen-edge containment policy. `layout.rs:1161-1165` gives slider a 48px-tall logical hit track, independent of its narrower visual bar.
5. **Text raster / contrast.** `layout.rs:987-1002` ellipsizes labels to `rect.width-12`, places text at x+6 and `centered_baseline`; `render.rs:68-80` documents deterministic logical positioning but host-dependent Cairo toy-font outlines. Motion should tint/paint an inset or at most integer-pixel chrome offset, **not shift text baseline by fractional pixels**, particularly at output scales 1.5/2. `render.rs:871+` applies Cairo scene scale, so logical-vs-device alignment must be compared with reference PNGs. No pixel-raster regressions were proven by the unit tests.
6. **Unproven viewport coverage.** No independently executed pixel fixtures for `800x480`, `854x480`, `1280x800` or a 40px panel on each. Existing fixture-generating test `layout::compact_fixture_tests::compact_fixture_png` is ignored; its presence is **not** evidence of passing raster qualification. R1-18 should add deterministic scene snapshot comparisons at press progress 0 / 0.5 / 1, disabled+selected combinations, text origins, and exact `hits` equality before/after press; R1-17 should test real panel edge coordinates and touch cancellation. These should go into existing owning lanes, not this audit.
