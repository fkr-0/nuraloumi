## Status

- Host implementation only; **NOT hardware-qualified and NOT enabled**.
- Starting main: `65ddad6ad61d737167238b2b04fe5524e3bb1402`.
- No SL101 switch node, input-event code, or polarity has been established.

## Physical read-only investigation

With a working authorized shell on the tablet, collect **without writing sysfs**:

```sh
uname -a
cat /proc/bus/input/devices
ls -l /dev/input/by-path/ /dev/input/by-id/ /sys/class/input/
find /sys/devices -maxdepth 5 -type f \( -name 'sw' -o -name 'state' -o -name 'value' \) -print
```

Review input capabilities for `EV_SW`, specifically `SW_LID` (0) and
`SW_TABLET_MODE` (1), but neither is assumed to exist or map to this mechanism.
Review kernel DT and platform device provenance before claiming a GPIO/Hall
sensor; an accelerometer orientation change is not a proven slider switch.
For each candidate read value with the mechanism independently **closed,
opened, closed, opened** and record timestamps, exact device identity and
kernel/DTB identifiers. Determine polarity, stability, bounce, reconnect and
suspend/resume behavior from physical observations. A kernel `EV_SW` event-only
device needs its own event adapter; the current prototype reads only explicit
binary (`0`/`1`) sysfs attributes.

## Prototype contract

`nuraloumi-slider-observer` is a standalone opt-in binary. It never probes
arbitrary GPIOs or chooses a source automatically. Flags:

```sh
cargo run -p nuraloumi-shell --bin nuraloumi-slider-observer -- --help
# Replace the path and level ONLY after hardware verification:
nuraloumi-slider-observer --source /sys/VERIFIED_SWITCH/value --open-level 1 --max-samples 100
# --notify is an independent operator opt-in after proof and local notification qualification.
```

Every 100 ms it reads at most 64 bytes from the explicit sysfs source; only
exact `0` or `1` is accepted. A 300 ms stable baseline suppresses boot and
reconnection notifications. Every later stable changed state produces exactly
`Slider opened` or `Slider closed`. An unreadable/disappeared/non-binary
source resets the baseline; reappearance cannot produce a false notification.
No persistent service, package autostart or device change was made.
With `--notify`, the supported `nuraloumi-ctl notify --summary ... --app
NuraLoumi` IPC path runs through a two-second bounded command runner;
failed delivery is logged without retry storms. A single failed delivery is
not replayed after the state has stabilized.

## Acceptance gap

1. Acquire authorized read-only device access; establish signal provenance and
   polarity with physical open/close cycles. Neither is presently proven.
2. If no sysfs `0`/`1` signal exists, implement and qualify a bounded `EV_SW`
   input adapter instead of inventing a sysfs mapping.
3. Run a human-attended, opt-in canary with notification IPC and screen
   observation. Verify one toast/history entry per transition, none for
   startup, bounce, disconnection, resume, or unchanged state.
4. Independently qualify ARMv7 musl/no-NEON packaging and memory/CPU usage
   before adding this experimental binary to any SL101 release manifest.

## Follow-up: evdev adapter (2026-11-25)

sources and can observe mapped volume/display `EV_KEY` events. See

notification gating and physical acceptance. The previous sysfs prototype
is unchanged. Hardware/polarity and end-to-end notification delivery still
require attended SL101 qualification; this does not imply deployment.
