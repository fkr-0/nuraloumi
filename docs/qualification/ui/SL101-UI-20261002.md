## Current geometry contract

The current committed shell defaults are:

```text
panel edge    top
panel height  40 logical px
menu width    448 logical px
row height    48 logical px
theme         dark
```

The Cairo renderer independently uses:

```text
header height       48 logical px
primary row height  48 logical px
target menu width   448 logical px
min target width    400 logical px
max target width    468 logical px
```

Actionable hit regions are emitted only when their visible height remains at
least 48 logical px. This prevents a partially clipped row near an edge from
silently becoming a smaller touch target.

## Physical-input follow-up

Two physical checks remain intentionally PENDING rather than inferred from unit
tests:

1. Touch the four display corners and representative row/search controls on the
   real panel, confirming visual and hit-region alignment.
2. Navigate/open/search/back using the physical SL101 slider keyboard.

The tablet exposes the real devices (`Atmel maXTouch Touchscreen` and
`AT Raw Set 2 keyboard`), but no input-capture helper is installed. Installing
extra tooling was deliberately avoided during this copy-only qualification.

These two physical checks are suitable for the final RC1 operator pass; they do
not invalidate the automated geometry, touch-state-machine, keyboard-semantic,
strict-font, or live surface evidence above.
