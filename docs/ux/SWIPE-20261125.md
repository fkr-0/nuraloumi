# Swipe dismissal — notification history

`nuraloumi_shell::swipe::Swipe` is a touch-only horizontal intent recognizer.
Only explicitly supplied row IDs can begin it. Notification rows `view-{id}`
opt in; section headings, commands and menus elsewhere never opt in by default.

- Capture: 14 logical pixels, horizontal displacement greater than 1.25 times
  vertical displacement; vertical intent keeps existing scrolling behavior.
- Commit: 35% of actual row width, minimum 48 logical pixels, in either
  direction. Undershoot, stale IDs and cancel return the row to its position.
- State: pending → captured with signed offset → dismissed or cancelled.
  Capture suppresses click on release. A second contact cancels the gesture.
- Right: actionless local hide. No provider operation is requested.
- Left: provider Remove is registered for live notification rows. Removal is
  acknowledged only through successful provider execution and subsequent
  refresh; failure leaves the row visible and reports the backend error.
  In fixture mode both directions hide locally and never invoke a provider.
- Hidden IDs survive refresh while that ID remains in the snapshot. If the
  provider no longer reports the ID, its local tombstone is discarded. Local
  hides do not modify durable history and reset on process restart.
- Cairo/wl_shm: the real rendered row pixels shift inside the row's hit bounds;
  three bounded exit samples precede the list re-layout. Reduced motion skips
  exit samples and collapses immediately. There is no idle frame timer, GPU,
  shader or NEON dependency.

Platform limitation: these host tests validate semantics and Cairo pixel
displacement; physical SL101 touch, compositor scheduling and frame visibility
need separately supervised qualification. The existing notification list uses
keyboard selection rather than continuous wheel-based pixel scrolling.
