### Exact inventory

`crates/nuraloumi-shell/src/glyphs.rs` contains **72 row identifiers**, **35 distinct Nerd Font codepoints**, **33 distinct Unicode alternates**. The fixed pinned candidate below contains all 35 Nerd codepoints. 27/33 Unicode alternates are absent in *that same mono font* (they may be provided by other fonts, but relying on implicit fallback is unqualified). Run the deterministic script for the complete U+ list and affected row IDs:

    python3 scripts/qualify-nerd-font.py --font /path/to/TerminessNerdFont-Regular.ttf --sha256 EXPECTED_SHA256 --require-complete

Other paths: `render_menu_with_glyphs_and_scroll` in shell `lib.rs` creates a default Nerd glyph resolver when none is passed; several app surfaces call this wrapper. `nuraloumi-render-cairo/src/render.rs` uses Cairo's `select_font_face("Sans", ...)` in its *default* deterministic backend. Thus **a complete TTF on disk is not sufficient**: this default renderer does not open it directly. Fontconfig resolution of `Sans` is machine-dependent; its glyph coverage and cache state are not controlled by release packaging. `PackagedFontText` in `packaged_font.rs` does use FreeType `FT_New_Face` on an explicitly supplied canonical file path, with HarfBuzz and Cairo FT faces and no fontconfig lookup. It fails with `MissingGlyph` rather than silently searching installed fonts. This backend is currently an optional API, **not connected to the normal panel/menu render call path**. Merely registering the font with fontconfig does not activate `PackagedFontText`, and merely selecting a Nerd family in Pango does not prove a fixed font file.

The panel now has independently authored Cairo line icons in its source, and the Control Center category line icons in `layout.rs` are owned by another worker. Do not replace those with font glyphs.

### Graceful fallback and deterministic gates

`GlyphTable::resolve_with_coverage(id, contains)` now provides **coverage-aware opt-in resolution**: preferred glyph → opposite table's glyph → ASCII `*` → no icon. The callback must test the **actual chosen rasterization face** (cmap), not merely Unicode scalar validity. Unit tests exercise all four paths, including no-glyph. The current default resolver `resolve` is **not yet wired to that coverage test**: its Nerd preference remains an independent release blocker. This API does not alter rendering ownership or claim that rectangle glyphs are now gone on the device.

The script checks the immutable 72-entry source table for duplicates, extracts exact codepoints, hashes the specified font, reads every Unicode cmap with `fontTools`, and exits nonzero when `--require-complete` finds any missing Nerd codepoint. Negative gate: call with intentionally wrong `--sha256` and require exit code 2. No fontconfig daemon or tablet access is required.

For the **1024×600** target, ensure both 40px panel and launcher/menu glyph consumers are exercised in a host-rendered 1024×600 scene and a physical screenshot. Verify (a) no tofu rectangles or clipping, (b) initial and reopened menu, (c) missing/corrupt font fallback, (d) Cyrillic/Latin and arbitrary app names if supported, (e) menu scrolling/overlap, (f) no measurable first-frame regression. That scene/pixel proof is **not present in this worker's host test**.

### Size, memory, and performance

The font adds 2.62 MiB compressed/uncompressed file input *before* tar/APK compression; no dependency on CPU ISA. An mmap of font data may share file-backed pages across processes, but one FT face, HB font, Cairo caches, glyph atlases, and surfaces have workload-dependent additional heap/RSS. **Actual SL101 incremental RSS and warm/cold glyph render latency are unknown**; no invented numbers are provided. Reject if aggregate idle shell exceeds **35 MiB RSS**, menu-open increment exceeds **12 MiB**, first interactive frame exceeds **250 ms**, or steady software interaction exceeds **33 ms** (16 ms preferred), measured on ARMv7/musl under the real compositor.
